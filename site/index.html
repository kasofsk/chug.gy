Why Chuggy

With Great Agents Comes Great Responsibility

Agents are powerful but need structure to thrive. Chuggy provides battle-tested scaffolding for agents to work on, ensuring high quality output and solving the most important cross-cutting problems. Today's largest platforms were simply not built for agents, and their legacy workflows map poorly onto agentic workflows and hinder adoption and efficiency.

For software development in particular, there is a widening gap between today's dev work and legacy dev platforms. Small teams now need features which used to be only for big companies, yet must remain nimble and lean. Big companies need specialized ways to centralize control to enable non-technical employees to safely use agents. Few tools can serve both naturally and Chuggy is one of them.

How it works

Tickets

Users define work as tickets. Chuggy facilitates ticket creation such that a ticket always conforms to a projects' standards and practices. Chuggy dispatches a specialized agent to work on each ticket, whose output is subject to a standardized evaluation process.

Graph Engineering

Tickets can depend on other tickets and only start work when all dependencies are met. This allows for releasing large amounts of work to many autonomous agents for long periods of time. By breaking the work into structured tickets, agents are always working on appropriately scoped tasks and output is continuously evaluated.

Complete History

Chuggy saves everything every agent does, its complete trajectory and output, and all evaluation results, made available for analysis and audits. These records may also serve as the basis for an outer evaluation loop by which Chuggy optimizes your project operationally over time.

Private and Secure

Chuggy supports both hybrid cloud and on-prem deployment. In either mode, all agent work and evaluation happens on your machines so sensitive data never needs to leave your system.

The Life of a Ticket

  1. DraftFreely iterate on instructions and configuration
  2. ReleaseReady for work when all dependencies are met
  3. WorkAn agent follows the ticket's instructions
  4. EvaluationTesting, QA, agent or human review, all according to your standards
  5. DoneCommitted to your repo, saved to a shared drive, jhatever Done means.

Built on itself

Chuggy's own development runs on Chuggy. Each change is a ticket going through the exact same process users use. Chuggy is the ultimate dogfood.

The core is a formal model specified in Quint. The primary service is public on GitHub, and the agent runners for Linux, macOS and Windows are open source. The docs describe how a project is set up and how its jobs run.
